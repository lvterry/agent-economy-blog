写代码的成本被智能体压下去之后，瓶颈转移到了另一头：人类还能不能跟上并理解这些改动。Whiteboard 这个开源桌面应用就是冲这个问题来的。

它的形态是一块画布，接上 Claude Code、Codex 等编码智能体后，智能体通过专门的 SDK 在画布上把工作画出来——时序图、实体关系图、或者从自身 trace 里摘出的片段。关键设计是双向可点：点图形能跳到对应的代码位置，读代码时又有 VS Code 的快捷键与 LSP 支持，使用的是 vendor 进来的 Code OSS 内核。

几处针对智能体时代的取舍值得留意。一是语义 diff：他们用 Rust 写了一个 AST 感知的差异查看器，大型新增函数折叠成伪代码，测试与文档改动默认隐藏，避免被噪声淹没。二是决策日志：智能体可以查询并链接自己的 trace，让人看清哪些决定是它自主做出的、如何影响这次改动——这正是当前 Plan Mode 最缺的部分，后者只能整份接受或整份打回。

项目用 MIT 许可、跑在本地代码检出之上，团队版托管服务在计划中，并承诺永远可自托管。

Hacker News 上的气氛是认可加追问。有人称赞接口干净，认为“理解代码库和软件设计”即将成为一个新行业；也有人质疑图的准确性，指出官方示例里有一处标注与实际 diff 对不上。这类担心并非多余——如果智能体画的架构图本身会产生幻觉，那它节省的认知负担很快会被验证成本吃掉。工具的成败，取决于图和代码之间那条双向链接是否真的可信。
