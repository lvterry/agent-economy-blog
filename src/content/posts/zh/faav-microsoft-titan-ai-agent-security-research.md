安全研究员 Faav 公开了他在微软内部服务 Titan 上发现的漏洞。Titan 的前端要求员工 VPN 才能访问，但他自建的 AI 猎洞机器人 Antares 找到了未被链接的公开 Swagger 文件，其中四个接口里只有接受原始 SQL 的 /v2/Query 没有强制 Azure AD 认证。

接下来十天，Antares 用 Codex 和 Claude 逐层拆解 JWT 校验逻辑：依次通过租户、受众、应用白名单检查，只是每换一个假设就撞一次新错误。真正的破绽是签名——载荷怎么改都被接受，说明 Titan 根本没验证签名。随后用一个 alg 为 none、签名为空的伪造 token 就绕过了认证。

机器卡住的地方恰是人类的用处。模型一直把 upn 当作邮箱格式的身份来猜，始终命中不了本地用户表；Faav 想到后端可能把 upn 当本地用户名，改成 admin 后直接命中本地用户 ID 1，也就是管理员角色，SQL 开始执行——"有时候答案真的就是 admin"。

可达范围包括约 2.5 万条账号与邮箱记录、1.8 万条员工邮箱、Bing 搜索分析数据；30 个存活路由值经 24 个配置解析到 17 个分析库、9863 张表，元数据估算总量为 17,333,335,124,315 行。微软按漏洞赏金计划奖励 5000 美元，HN 社区认为这个金额与影响严重不匹配，也对微软要求对披露文章保留编辑权提出不满。

Faav 的总结值得记下：AI 替他做了十天的枚举与试错，省掉了大量机械工作，但把 upn 从"邮箱"重新理解成"本地用户名"的那一步，仍只有人能完成。这大概就是眼下智能体参与安全研究最真实的样子——苦力交给机器，判断留给人。
