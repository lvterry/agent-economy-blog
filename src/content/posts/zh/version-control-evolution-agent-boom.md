AI 智能体正在以远超人类的速度生成代码。单个会话中，一个智能体可以创建数百个文件、执行数千次工具调用。传统版本控制系统——Git——记录的只是最终写入磁盘的文本行，而代码产生的过程——提示词、工具调用顺序、中间检查点、决策理由——全部丢失。

Entire 是一家面向智能体时代重新设计 Git 托管的初创公司。他们在最新博文中提出一个核心论点：**会话日志已经成为软件开发中最重要的工件，应当与代码一同存入仓库。**

这意味着将智能体的每一次操作记录为结构化的"语义记忆层"。当新智能体加入项目时，它不再需要从头扫描代码并猜测设计意图——它可以读取过往会话日志，理解每个文件为什么以这种方式存在。Entire 认为，这种记忆层不仅能提升智能体的准确性和生产力，还能显著降低 token 消耗，因为智能体不再需要重复推理已知的上下文。

更深层的变革在于 Git 托管架构本身。当前 GitHub、GitLab 等集中式平台构成了单点瓶颈。当数以千计的智能体并行工作、频繁进行读写操作时，集中式架构的限速、宕机和延迟问题将被放大。Entire 主张回归 Git 的原始承诺——真正分布式的网络，仓库可以存在于任意多个节点，智能体可以在本地或就近节点高速读写，然后异步同步。

这一思路与智能体经济的演进方向一致：当智能体成为软件开发的主力，工具链必须从"面向人类阅读"转向"面向智能体协作"。版本控制的下一个十年，可能不再是文本差异对比，而是会话回放、决策溯源和分布式同步。
